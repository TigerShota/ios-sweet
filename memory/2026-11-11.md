## GPU CP hang 的真正根因（关键，纠正此前判断）
此前以为根因是 iova 复用走旧 TLB。从 v117 真机日志 + `gauguin_gpu.c` 源码确认，**真正的阻断是 boot 时锁存的 `CP_HW_FAULT`（bit 18 = `0x40000`）从未被 ack**：
- 源码 `gauguin_gpu.c` ~3952–3961 行注释明确：SQE 在 boot 释放后即锁存 `CP_HW_FAULT`，"a latched HW fault can make the ME refuse a chained IB"。
- v117 日志实证：`MMIO mapping failed=0`、`SMMU gfsr=0`（非映射失败、非 TLB 翻译错）；但 `submit state HUNG ... fault=0x40000` 常驻，rptr 追上 wptr 后在 IB 上 STUCK；`|backboardd| MESA: submit failed: -60` 出现 **728 次**，`no ring space` 764 次。
- backboardd / SpringBoard 都活着（日志 28000+ 次提及），但每次 GPU 提交都 -60 → **桌面永远渲染不出来** = "进不去桌面"。
- 全局 TLB 失效（0125 已加）和 0170 的 per-map TLB flush 只能让 ring 多走几步（rptr 1852→1880），**治不了锁存的 HW_FAULT**。

### 修法 = 启动参数，不改代码
- boot-arg `gauguinclr`：`PE_parse_boot_argn("gauguinclr")` → `gg_clr_opt`。取值 **1**=W1C `CP_INTERRUPT_STATUS`、**2**=submit 前 `gauguin_gem_tlb_flush()`、**3**=两者、**4**=再加 W1C `CP_HW_FAULT`。
- **`gauguinclr=4` = W1C 中断状态 + W1C `CP_HW_FAULT(0x40000)` + TLB flush**，正好清掉锁存故障 → ME 不再拒链式 IB。
- v117 用 `gauguinclr=0`（不清）→ 锁存 fault 一直卡 IB。此即"进不去桌面"的直接元凶。
- **记忆点**：任何"ring 通了但 IB 卡死"的 hang，先试 `gauguinclr=4`，别急着改 GEM 页表代码。

## 补丁链与验证手段
- **0157** (`gauguin-cp-drop-nested`)：按 `gauguinmark=4/5/6` 把 `CP_INDIRECT_BUFFER(0x3f)`/`CP_WAIT_FOR_IDLE(0x26)` 整包 NOP。结论：**逐包 NOP 只能把挂点推后，根因未解，路线已关闭**；嵌套 IB 本身（映射/权限或嵌套偏移的 `0x70438003`）才是真问题，但已被 `gauguinclr=4` 在更高层绕过。
- **0158** (`gauguin-clear-fault-tlb`)：引入 `gauguinclr` boot-arg（默认 0）。四个等级全部无效（W1C 读回仍是锁存值）→ 确认 HW_FAULT 不是可清状态位，需 `gauguinclr=4` 的 W1C 路径（见上）。
- **0159** (`sweet-panic-log-flush`)：**panic 文本落盘机制**。在 `_cnputs`→`sweet_log_append` 里匹配 `"panic(cpu"` 后增量 flush（无 mutex、无 printf、防重入），之后任何 panic 都能自动进 4 MiB RAM 环并被 `gpu-pull-log.py` 抓到。0123/`fajita` 同类 panic 已知。
- **0160** (`gauguin-touch-tlmm-window`)：修 `0x5b0000`→`0x5b000` 笔误，消除触摸线程 panic。

### 上机验证流程（已固化）
1. OrangeFox recovery 下清零 SWEETLOG 头块：`real=/dev/block/sda35`（即 `userdata`），`skip=size/4096-1025`（≈28055546），`dd if=/dev/zero of=$real bs=4096 seek=$skip count=1 conv=notrunc`。重引导后若该块变 `SWEETLOG` 即证明 XNU 真启动写盘。
2. `fastboot boot out/vXXX/shim/out/shim-boot.img` → 进 XNU 跑满 300 s（覆盖 GPU ladder）→ 手动 power-cycle 回 recovery。
3. `python tools/gpu-pull-log.py vXXX` → `out/sweetlog-vXXX/vXXX.{txt,bin}`（约 4 MB ring）。
4. 判据：`impl 0160` 出现、`panic(cpu`=0；对 GPU hang 看 `fault=0x40000`/`submit failed: -60`/`no ring space` 是否归零。

## 结论一句话
"进不去桌面" = boot 锁存的 `CP_HW_FAULT=0x40000` 让 GPU ME 拒绝链式 IB → backboardd 每次提交 -60。修法是 **`gauguinclr=4`**，不是改页表（0170 的 per-map TLB flush 只是辅助、不治病根）。v118 已就绪待验证。

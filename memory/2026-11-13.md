## v140 实测（日志 `out/sweetlog-v140/v140.txt`，947,824 B / 18,059 行，header 正常）
用户报告画面：**紫色方块 + 白条 → 继续滚动 log → panic**，仍无 logo / 锁屏。

- `impl 0191` 1、`0189 ring size=8192` 1、285 `submit cp done`、286 `mark count`、
  3 HUNG / 5 STUCK / `no ring space=0`、FB swap 3、`src/panel px` **6/6 全 0**。
- 首次 HUNG：`fence=0x600011b rbbm=0x800005 status1=0x8100031e
  roq=0x50003f sqe_pc=0x4:0x2883003f rptr=6614 wptr=6606`。
- **0191 精确定位**：
  - `0191 stop ib=2 iova=0x56162000 at=1360 of=2411 rem=1051`
  - `0191 frame hdr_at=1359 hdr=0x48810385 type4 reg=0x8103 count=5 payload=1
    reg_at=0x8103 name=GRAS_LRZ_BUFFER_BASE_LO`
  - `0191 lrz base=0:0 pitch=0 fc=0:0 clk=0 gras=0 lrzclk=0`
  - `0191 progress rem=1051->1051 rptr=6614 wptr=6606`
  - 包帧 `1352: ... 0x48810385` / `1360: 0 0 0 0 0 0x70bf8003 0x5616a000 0`
- **结论**：CP 卡在写 `0x8103..0x8107`（`GRAS_LRZ_BUFFER_BASE` / `PITCH` /
  `FAST_CLEAR_BASE`）这条 Type-4 的**第一个 payload**；5 个 payload 全是 0，寄存器读回
  也全 0，且只有 `CP_AHB_CX + GPU_BUSY`。即：该 AHB 写永不完成，而它本来就是"写全 0"，
  **长度保持 NOP 在语义上完全等价、零副作用** —— 这是十几版以来第一个能精确瞄准
  且不会破坏硬件状态的改动。
- **命名纠正（避免误判）**：0191 的 `clk=0x000ae` 是 `RBBM_CLOCK_CNTL`，
  `gras/lrzclk=0x000c8/0x000c9` 实为 `RBBM_CLOCK_CNTL3_TP0/TP1`（Texture Processor），
  **不是 GRAS/LRZ 时钟**，不能据此断言 LRZ 时钟未开。

## panic 归因（纠正：不是新现象，不是 0191 引入）
- 文本：`kmem_alloc(0xfffffe1011984a30, 16384, 0x100021): failed with 3 @vm_kern.c:178`
  → `panic(cpu 4 ...)` → `handshake structure not initialized`（后者只是 kdp 输出，非病因）。
- v136 / v138 已有同类 16 KiB panic，`NOTES.md` 记为 "known unrelated kmem_alloc panic"。
- `failed with 3` = `KERN_NO_SPACE`；`ml_io_map()` 从 **8 MiB IOKit `io_submap`**
  （`osfmk/arm/io_map.c`，`IO_MAP_SIZE (8ul << 20)`）分配且 `KMA_NOFAIL`；
  `gg_san_map()` 的 8 页缓存在轮换时**不 unmap 旧页** → 累积耗尽 → 启动后期必崩。
- 与 GPU wedge 独立：GPU 停点在日志 14,057 行，panic 在 18,058 行，判读不受影响。
  待后续单独修（unmap 旧页 / 减少逐 dword 映射），本轮未混入 v141 以免污染判读。

## 工程踩坑
- `gh` 必须带 `--repo TigerShota/ios-sweet`（默认仓库会看错）。
- Windows git push 走代理需 `git -c http.sslBackend=openssl -c http.proxy=... -c https.proxy=... push`。
- `gh run download` 的 artifact 常多套一层目录（`gauguin-shim-boot/shim/out/...`），
  必须递归找 `shim-boot.img` 再归一化到期望路径。
- 强制断电会清掉 SWEETLOG header：`sweet-log.py` 会拒绝解析，需从 `.bin` 偏移 4096
  起按可打印字符兜底恢复文本（v132 遇过）。
- `xnu.yml` 的 push paths 只含 `xnu/patches/**`，纯文档推送不会触发内核构建。
